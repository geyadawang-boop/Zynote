计分口径

  • 每个功能资产 = 1 份资产，内部再分 需求 0.35 + 契约 0.25 + 实现 0.40。
  • 资产权重 = 终版有效代码量 45% + 难度 20% + 采纳度 15% + PR/合并历史 12% + git 工时 8%，归一到 100。
  • 实现段用继承系数 α：界面类 0.68、后端 0.40、协议/交付 0.15–0.30，其余部分归重写者。
  • PR 历史取 18 个已合并 PR 的采纳行数；meiji PR #1 是合并总 PR，已剔除，避免 4.8 万行重复计数。
  • 这是自定义折算，不是 GitHub 官方统计；分项四舍五入，尾差 ±0.1。

局限

  • 资产归并与难度评分含人工判断，依据逐条写在证据列，可复核也可反驳。
  • git 工时只反映提交跨度，不代表实际投入时长；离线设计与调试无法计入。
  • 重写导致同一功能存在两套实现，本口径只计一份资产，不重复计分。
