## 描述

B站账号扫码后，视频学习的分集/字幕请求仍使用匿名 HTTP 客户端；资源页只有列表，不能在软件内浏览 B站网页并导入当前视频；课件与转写下载另走 SnapAny。

本 PR 用现有 Go 会话作为鉴权来源，将分集、字幕及字幕同步接入同一 Cookie owner；增加隔离的 Electron 浏览窗口，从加密档案恢复 Cookie，并通过原生菜单/右键菜单把当前视频和分P导入现有视频摘要、字幕或课件页面。摘要继续使用现有 video-ppt:summary、引用校验、课程保存和导出格式，无站内字幕时复用本地转写。课件/转写的下载复用原生 catalog/transfer/mux，不再依赖 SnapAny。

同时修复扫码成功缺少凭据仍被接受、保存错误被吞、解密失败被缓存，以及 Cookie host-only/path/Max-Age 范围问题。远程网页无 preload/Node/应用 IPC；Cookie 仅经 Go→Electron 内部桥传递，外部导航与重定向受限。打开/退出串行执行，切换扫码身份及退出账号清理旧窗口。Rust 原生处理职责及依赖保持不变。

验证：
- `pnpm verify` 通过（TypeScript、Biome、action contract）。
- `go test ./...`、`go vet ./...` 通过（Windows amd64 / Go 1.27.3）。
- 浏览 URL/分P、远程页面隔离、host-only 恢复、导入事件和退出竞态：Vitest 11项通过，使用 Electron mock。
- Go 回归包含真实 HTTP fixture 下的扫码必要凭据、保存失败、重启恢复、解密恢复及带鉴权字幕获取/CDN无凭据。
- `pnpm build` 通过，Go core 冒烟通过；原生 PDF 桥因缺少 native binary/pdfium 按脚本跳过。

保持 Draft：真实手机扫码、B站网页播放、受保护视频下载、真实 ASR/模型摘要和 macOS/Windows 双主题目检尚未完成，不能把受控测试视为外部服务验收。Rust 全量回归尝试过：默认1.89低于依赖MSRV；使用已有1.94后，Windows vendored OpenSSL 因本机 Perl 环境失败。没有修改 Rust 源码、锁文件或降级依赖规避该问题。

当前浏览窗口在打开时从 Go 档案恢复；网页内自行重新登录不自动写回 Go，请在账号页扫码以统一身份。不声称永久免登录或绕过平台访问限制。说明见 `docs/BILIBILI_SESSION.md`。
