## 描述

## 背景

“研究与工作流”板块用两份真实课程字幕（智云《微积分（甲）Ⅰ》148 分钟、B 站《高等数学 30 泰勒公式》45 分钟）和 `qwen3.7-plus` 实测，发现以下问题：

1. 引用核验只检查 `[S1]` 编号，编造的“老师原话 + 时间”也能通过，违背“每条引用都能核对出处”。
2. 回答把引用写成 `[S1, 14:06-14:22]` 这种更精确的格式时，被判为“缺少有效来源编号”，整段丢弃。两步工作流第一步实测 2/2 失败。
3. 每份资料只截前 3 万字，而字幕按原始 SRT 存储，148 分钟的课只读得到前 55 分钟；问后半节内容时，会笃定地回答“没有找到”。
4. `overview` 把每个任务的全部原文（约 20 万字）原样返回。6 个任务就超过主进程单行 100 万字符的上限，回包被丢弃，研究页和任务中心每次都要卡 90 秒。
5. 每个请求都新建 Engine 并做“中断恢复”，研究进行中只要一刷新（任务中心每 3 秒轮询一次），运行中的任务就被误标为“上次模型请求中断”。

## 改动

- **原话级核验**（新文件 `backend/internal/research/citations.go`）：
  - 回答中带来源编号的引号原话，逐句回原始字幕比对：忽略标点、语气词和插注，按所注时间 ±90 秒定位，用半全局编辑距离判断；
  - 结果分为“原文一致 / 有删改 / 时间不符 / 待核对”，对不上的不再整段丢弃；
  - 界面逐条显示原始字幕和时间，导出的研究 Markdown 附核对记录。
- **引用格式**：兼容 `[S1]`、`[S1@00:14:06]`、`[S1, 14:06-14:22]`、`[S1, S2]`、`【S1】`；提示词要求原话写成 “原话”[S1@时:分:秒]。
- **整节课可读**：
  - 字幕以紧凑行 `[时:分:秒]原话` 交给模型（微积分 80,328 → 49,845 字），10 万字预算按水位线公平分配；
  - 每份所选资料都进入阅读清单，修复选 5 份以上长资料后核验和导出必失败的问题；
  - 没读完时如实标出“只读到 hh:mm:ss（全长 …）”，并要求模型不得把未读部分说成“没有”。
- **列表瘦身**：`overview` 列表不再带原文（原文仍保存在任务记录里，供核验和导出），实测 6 个任务的回包从超过 100 万字符降到 12,292 字符。
- **中断恢复**：每个后端进程只做一次。
- **超时**：`tools:request` 改用长任务超时。整节课一次研究实测要 60–122 秒，原来的 90 秒会误报超时。模型客户端自身仍有 180 秒上限。
- 回答被拒时保留原文（截断到 4000 字），供排查；删除“研究 Agent 最多八轮”等不实说法。
